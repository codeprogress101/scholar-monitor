## Fixture, privacy and capture method

Used existing disposable eligibility/managed-payroll/payment/omitted/import drivers and genuine synthetic accounts. The financial examples have two or three source scholars; the import browser fixture has 19 synthetic profiles, including three reviewed historical members and truthful Course pending placement. Synthetic registration, masterlist approval, batch review/finalization, processing, reconciliation/closure, document preparation, cancellation and an acknowledged individual settlement were performed only in owned disposable databases to expose real states. Bulk Paid/Unclaimed previews in the final three-member fixture were cancelled without recording outcomes. No operational feature was activated in main development.

One ignored, task-local copy of the import fixture declares regular first-semester identity before receipts and supplies the server's current coverage hash, using existing setup services. It changes no application reader, safeguard, test expectation or financial rule. Earlier calendar invalidation correctly produced a source-change blocker, captured separately. Fixture preparation and harness failures remain in private evidence; they are not represented as a new complete UAT pass.

Captured at device scale factor 1 / visual scale 1 with consistent browser zoom. Ordinary captures wait for network idle, loaded fonts and visible loading/checking labels to settle. Only the labelled loading and injected read-only 503 examples intentionally interrupt that process. No password was captured. Business Scholar IDs identify fictional fixture scholars; random hexadecimal strings in imported names are fixture-generated name material, not database keys. Internal transaction/audit IDs are obscured by bright magenta capture masks; those bars are evidence redactions, not application styling defects. Existing public municipality/LDSS branding and printed form labels are retained.

All PNGs were decoded/verified and all selected role/state pairs checked for both dimensions. Representative contact sheets from every module and important full-page forms/reports were visually inspected. The package index passed module/role/search filtering and loaded-image checks through a public-file-allowlist loopback server; all 1,063 HTML file references and portable Markdown links resolve locally. Direct `file:` automation was blocked by the browser tool, so normal direct-file opening is not claimed as browser-tested. This is not a claim of pixel-by-pixel or OCR verification of every image. Some long-page top viewports repeat while the full-page images show distinct lower forms. Full-page capture of a sticky sidebar can place it mid-image; that capture artifact is not a demonstrated runtime defect. For the fixed landscape official form, the tablet viewport scrolls horizontally by design; its full-page image retains the document width.
