# A2 — Existing scholar → approved Excel import readiness

25 October 2026, Philippine time. **Focused documentation/source review only. No implementation authorized or started.**

**Finding: the existing A2 documentation is not implementation-ready for this case.** It establishes identity reuse and immutable provenance, but does not specify how a later approved Excel row attaches to an existing manual annual intake. Recommend **A2.1 — reviewed identity reuse and immutable import/intake binding**, initially for registration-only scholars. This closes the normal A1/A5 → approved-import handoff without redesigning imports or repeating the system-wide review.

## Recommended solution: append a link, retain both sources

Keep the existing person/permanent ID and original manual intake unchanged. Add a separate immutable **`import_intake_bindings`** table for explicitly reused manual rows. Do not add another annual root, switch `origin_kind`, update original supplied fields, or repurpose an intake supplement/classification correction as an import operation. Storing only an unvalidated client mapping or skipping the intake INSERT would leave the provenance contract incomplete.

Proposed binding: server UUID; import-job FK; actual worksheet row; intake-root FK; reviewed person version; intake revision/snapshot hash; raw-row hash; identity-review reference; canonical binding hash; actor and real recorded time. Use a versioned snapshot format. The intake FK determines person/year, avoiding redundant competing ownership columns. Require **unique `(import_job_id,source_row)` and `(import_job_id,intake_id)`**, restrictive FKs, no-update/no-delete triggers, and own-schema **SELECT/INSERT only**. A single intake may have multiple historical source links structurally; this does not authorize another scholarship decision or entitlement.

### Bounded A2.1 behavior

1. **Review identity explicitly.** Keep the eight-column workbook unchanged. Extend approved-import preview/staging with strict per-row identity resolutions: actual row, selected existing person and current version, current manual intake ID/revision/hash, current duplicate-review snapshot, explicit same-person confirmation and evidence reference. Bind these to the exact workbook and preview hashes. Return structured candidates using the existing duplicate algorithm/bounds and confirmed permanent-ID display; never auto-match a name. Duplicate row/target mappings, forged/out-of-year roots, ambiguous identity and stale evidence block confirmation. Restaging creates a new immutable job; existing previews are not edited. Unmatched new-person rows retain existing duplicate checks; there is no import-level create-separate bypass.
2. **Limit the first release to registration-only reuse.** Require the matching manual root for the working year and no established academic record, annual scholarship record or participation for the reused person. Existing academic/annual/participation evidence needs its current controlled workflow; do not skip its guards or pretend A2.1 handles every already-approved scholar. Check effective intake classification against Excel after existing Old → Continuing normalization. Conflicting known initial placement/classification blocks the row; unknown initial facts may remain unknown in the original intake while the import separately establishes supported academic facts. Use existing normalization only, not guessed equivalence or progression.
3. **Confirm atomically.** Retain existing authorization/configuration lock order, exact retry, fresh-preview validation and same-connection service adapter. Reuse the person without calling its profile writer or consuming another ID; preserve person version/contact/first-entry year. Lock/recheck the manual intake and append its binding **instead of inserting another intake**. Run the same authorized academic, qualification and continuing-baseline operations as an approved simple import. For reused Continuing scholars, pass the actual reviewed person version; the current importer assumes version 1 for newly created people. Any later failure rolls back the binding and all new import effects. Audit created versus reused rows and their source IDs.
4. **Retain separate approvals.** Approved staging/confirmation stays under existing Coordinator permission checks and all underlying operation permissions. Identity reuse is not selection, COR/COG verification, prior-review adoption, publication or payment authority. Existing Course pending confirmation, actual receipt assertions and separate Coordinator prior-batch review still apply. Missing history/dates/documents are never invented.
5. **Version the confirmed source.** New binding-aware results preserve existing `items` IDs/row numbers and identify each row's source: unchanged import-origin root for a newly created person, or immutable binding ID/hash for a reused manual intake. Keep original Excel cells and manual history separately readable. Use one server-side confirmed-import-scope resolver to verify the complete one-to-one raw/preview/result/binding ownership, hashes and year. New-format markers cannot silently fall back to legacy interpretation when links are missing or malformed.
6. **Preserve downstream compatibility.** [Prior approval](../../server/requirements/prior-approval-service.ts:33) and [historical append](../../server/payouts/historical-append.ts:27) currently derive membership from confirmed result IDs, not intake-origin reassignment. Integrate the resolver there and in [fresh historical-source validation](../../server/payouts/historical-context.ts:42). Reuse the existing import/preview/result fingerprint for new sources; do not rewrite legacy JSON, hashes, prior reviews or frozen evidence. Binding pins describe the reviewed intake revision historically. Later intake corrections remain visible and use their separate controlled academic/admission disposition; they do not silently rebind imports or alter frozen financial sources. No new intake-head dependency is added to legacy payment eligibility.

Reject incompatible established records and source changes visibly. Do not use `INSERT IGNORE`, REPLACE/upsert, auto-merge, fabricated omissions, automatic re-adoption or a second financial route. Query matched roots/bindings as bounded sets within the existing 1,500-row import limit; no new per-scholar eligibility/history fan-out.
