## Consistent shell and task hierarchy

Retain React/TypeScript, Bootstrap, existing Lucide icons, dark-green/cream identity, `FocusedDialog`, `WorkspaceUI`/`PagedTable`, `ErrorNotice`, current navigation, role checks and scoped styles. Reuse spacing/typography variables after checking computed styles; do not perform a global stylesheet rewrite to make screens look different.

Each screen has one primary task heading, compact selected context, a relevant action/search row and the task content. Secondary setup/history uses existing disclosures. Required evidence, financial blockers, retry controls and approval explanations remain immediately available. Destructive/correction actions remain distinct from routine work. Do not replace source-specific financial states with a universal stepper or cosmetic progress percentage.

## Shared accessibility and responsive acceptance, B6

| Test area | Required future evidence |
|---|---|
| Width/reflow | 1440, 1024, 820px and supported smaller widths; 200% native browser zoom; separate 320 CSS-pixel non-table reflow. Ordinary controls/headings/messages stay in viewport. Wide data tables may use labelled scroll regions, not page-wide overflow; official landscape print views are evaluated separately |
| Shell | Reuse the existing drawer rather than a second sidebar. Evaluate the breakpoint from constrained content width; current <=650px behavior remains. Escape, focus return, inert background, resize and role-specific destinations survive |
| Keyboard/focus | Logical order, skip link, visible focus, functional tab/link semantics, drawer/dialog entry/containment/Escape/return and page navigation. No sticky banner/toolbar completely obscures focus; aim to keep the whole focused control visible. No hover-only disclosure of essential names/status |
| Data tables | Accessible names/captions/headers, exact permanent IDs, complete name via wrap or keyboard/touch-operable detail, monetary alignment/tabular figures, explicit cross-page selection and scroll affordance; no lost action columns |
| Forms/errors | Visible full labels, required/optional meaning, errors associated with fields, actionable reason and authorized owner/destination. Preserve reference/evidence truth. Validation, permission loss, stale review and uncertain outcome have different recovery paths |
| Dynamic states | Contextual status announcements for counts, loading and commit results without focus theft or duplicate live regions; use screen reader testing where available. Do not announce zero or success while unavailable/unconfirmed |
| Contrast/motion/targets | Guide's normal-text 4.5:1/large-text 3:1 targets; non-color state cues, existing reduced-motion handling and readable text scaling. Comfortable 44 CSS-pixel targets are a design goal, not a claim that all AA targets require 44px |
| Financial confirmations | Counts/amounts/actual date/source visible; each required acknowledgment initially unchecked; cancel/back reachable; reviewed accepted set and all-or-nothing commit unchanged; reload preserves exact uncertain request/key and navigation remains locked until resolved |

The guide targets WCAG 2.2 AA; these planned checks do not certify conformance. A small CSS-only fix needs focused component/browser validation; shared shell changes need representative role/state regression. No test should merely assert cosmetic class names while ignoring task behavior.

## Rollback and boundaries

Revert presentation by screen, keeping public routes, pending command storage and legacy preference readers compatible. Do not clear browser retry state to make a redesign work. A shared shell rollback reverts its breakpoint/state/focus changes together. Annual/monitoring changes require their own data-compatible rollout, not a CSS rollback. UI work can be separately authorized without PB1/PB2/PB6 resolution when it preserves those boundaries; it cannot approve official forms, change period guards, enable flags, amend payments or establish faster services. Service optimizations belong to the [measured roadmap](../performance/LDSS_OPTIMIZATION_ROADMAP.md).
